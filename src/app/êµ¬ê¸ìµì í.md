# GOplanAI 구글 검색 엔진 최적화(SEO) 아키텍처 가이드

본 문서는 GOplanAI 플랫폼의 마켓(Market) 기능에 적용된 서버 사이드 렌더링(SSR) 및 검색 엔진 최적화(SEO) 기술 구조를 상세히 설명합니다.

## 1. 핵심 아키텍처: Server-First 전략

기존의 클라이언트 사이드 렌더링(CSR) 방식은 브라우저에서 자바스크립트가 실행되어야 데이터가 보였으나, 현재 마켓 구조는 **Next.js Server Component**를 기반으로 설계되어 구글 봇(Googlebot)에게 즉시 완성된 HTML을 제공합니다.

### 1.1. Firestore REST API 기반 페칭 (`server-fetch.ts`)
- **문제 해결**: 서버 환경에서 `firebase-admin` 라이브러리의 인증 토큰 갱신 오류(500 에러)를 방지하기 위해 도입되었습니다.
- **로직**: SDK 없이 순수 HTTP `fetch`를 통해 Firestore 데이터를 가져옵니다. 인증 제약이 없는 공용 데이터를 대상으로 하므로 가장 빠르고 안정적입니다.
- **보안**: 마켓 전용 컬렉션(`market_items`)은 읽기 권한이 개방되어 있어 REST API 호출에 최적화되어 있습니다.

### 1.2. 동적 메타데이터 주입 (`generateMetadata`)
- 각 기획안 상세 페이지(`/market/[id]`)는 해당 문서의 제목과 요약문을 기반으로 구글 봇에게 고유한 메타 태그를 전달합니다.
- 이를 통해 구글 검색 결과에서 사이트 이름이 아닌, **실제 기획안 제목**이 직접 노출되어 클릭률(CTR)을 극대화합니다.

## 2. ISR (Incremental Static Regeneration) 구조

성능과 비용을 동시에 잡기 위해 **ISR 기술**이 적용되었습니다.

- **설정**: `export const revalidate = 3600;` (1시간)
- **작동 원리**:
  1. 첫 방문자가 접속할 때 서버에서 HTML을 생성합니다.
  2. 생성된 HTML은 1시간 동안 정적 파일로 캐싱됩니다.
  3. 이후 방문자들은 서버 연산 없이 **광속으로 로딩**되는 정적 페이지를 받게 됩니다.
- **장점**: 수천 명의 유저가 마켓에 동시 접속해도 Firestore 읽기 비용이나 서버리스 실행 비용이 추가로 발생하지 않습니다.

## 3. 동적 사이트맵 연동 (`sitemap.xml`)

구글 봇이 마켓의 모든 글을 빠짐없이 발견할 수 있도록 자동화된 사이트맵 엔진을 구축했습니다.

- **파일**: `src/app/sitemap.ts`
- **로직**: 사이트맵 생성 시점에 `market_items`의 모든 ID를 실시간으로 페칭하여 URL 리스트를 구성합니다.
- **효과**: 사용자가 기획안을 '마켓 발행' 하는 즉시, 구글 서치 콘솔에 등록하지 않아도 구글 봇이 스스로 새 문서를 찾아내어 색인을 진행합니다.

## 4. 로봇 제어 및 보안 (`robots.txt`)

- **허용**: 홈, 마켓(/market), 템플릿(/templates), AI 기능(/ai-features) 등 공개 콘텐츠.
- **차단**: 내 문서(/my-documents), 프로필(/my-profile), 관리자(/admin) 등 개인 정보 관련 경로.
- 이를 통해 구글 봇이 중요한 비즈니스 콘텐츠 수집에만 집중하도록 자원을 배분했습니다.

## 5. 클라이언트 요소의 분리

- **서버 영역**: 제목, 본문, 이미지, SEO 메타데이터 (구글봇 타겟)
- **클라이언트 영역 (`MarketActions.tsx`)**: 로그인 체크, 템플릿 복제 버튼, 인터랙션 요소.
- **구조적 이점**: 검색 엔진은 텍스트에 집중하게 하고, 유저는 풍부한 상호작용을 경험하게 하는 하이브리드 구조입니다.
